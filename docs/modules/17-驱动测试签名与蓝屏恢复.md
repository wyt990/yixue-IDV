# 模块 17 — 驱动测试签名与开机蓝屏恢复

> 适用：`SysRestoreDriver`（Windows 卷过滤驱动）测试签名、安装失败、BOOT_START 蓝屏恢复。
> 背景：2026-11-16 功能测试中，客户端开启 testsigning 后驱动仍加载失败并开机蓝屏。

---

## 1. 结论摘要（根因）

**开启测试模式后仍加载失败，是因为随包驱动根本没有签名（NotSigned），而不是"测试签名没生效"。**

| 事实 | 证据 |
|------|------|
| 原包 `SysRestoreDriver.sys` 无 Authenticode 签名、无证书表 | `Get-AuthenticodeSignature` → `Status=NotSigned` |
| INF 声明 `CatalogFile = SysRestoreDriver.cat`，但包内无 `.cat` | `deploy/client-package/driver/` 文件清单 |
| INF 把驱动注册为 **BOOT_START** 卷过滤驱动（FilterLevel 0x100、Upper、Volume 类） | `SysRestoreDriver.inf` 的 `[SysRestoreDriver_ServiceInstall]` / `_FilterInstall` |
| 安装脚本对 testsigning 仅 WARNING，仍继续写 UpperFilters | 旧 `install-driver.ps1:21-24,50-53` |
| 签名脚本先把未签名 sys 拷进包再签名，签名失败会留下未签名包 | 旧 `sign-sysrestore-testcert.ps1:60-72` |

机制：testsigning 只放行**已由测试证书签名**的驱动。未签名驱动在启动阶段被拒绝；由于它是启动卷的上层过滤驱动，拒绝加载会导致系统无法挂载启动卷，表现为开机蓝屏/无法启动：

- `0xC0000428` — Windows cannot verify the digital signature for this file
- `0x7B` — INACCESSIBLE_BOOT_DEVICE
- `0xC0000225` — 启动项/设备异常

> 若蓝屏码是 `0x7E / 0x50 / 0xD1 / 0x3B / 0x1E` 等，则不是签名问题，而是驱动自身缺陷或系统不兼容，需分析 MEMORY.DMP。

---

## 2. 修复内容（2026-11-16）

1. 用构建机测试证书重新签名 `deploy/client-package/driver/SysRestoreDriver.sys`；
2. 用 `Inf2Cat` 生成 `SysRestoreDriver.cat` 并用同一证书签名（INF 已声明 CatalogFile，缺失会导致安装/校验异常）；
3. `deploy/scripts/sign-sysrestore-testcert.ps1` 重写：
   - 复用现有 PFX（仅缺失时新建；新建后必须让客户端重新导入 .cer）
   - 在临时目录先签名+校验，成功后才覆盖客户端包（避免"半签名包"）
   - 自动生成并签名 catalog，输出前校验 sys/cat 均有签名
4. `install-driver.ps1` 重写为硬校验：
   - 管理员、Secure Boot=False、testsigning=Yes、sys/cat 签名 Status=Valid
   - 任一不满足直接 throw，**不再写 UpperFilters**
5. `enable-testsigning.ps1`：校验管理员 + Secure Boot；移除 `nointegritychecks on`（签名正确时不需要，且会削弱整机驱动完整性校验）。
6. 新增 `uninstall-driver.ps1`、`recover-boot.txt`（WinRE 恢复步骤）。
7. `使用说明-测试签名驱动.txt` 重写为完整的安装/判定/回滚/构建机签名流程。

## 3. 正确操作顺序

### 3.1 构建机（生成签名包）

```powershell
# 1) 编译（需 WDK/VS，见 drivers/sys-restore/build-driver-x64.ps1）
powershell -ExecutionPolicy Bypass -File drivers\sys-restore\build-driver-x64.ps1

# 2) 签名 sys、生成并签名 cat、发布到 deploy\client-package\driver
powershell -ExecutionPolicy Bypass -File deploy\scripts\sign-sysrestore-testcert.ps1

# 3) 必须两个都 Valid
Get-AuthenticodeSignature deploy\client-package\driver\SysRestoreDriver.sys
Get-AuthenticodeSignature deploy\client-package\driver\SysRestoreDriver.cat
```

### 3.2 客户端（试点机）

```powershell
cd "C:\Program Files\YixueIDV"
.\scripts\enable-testsigning.ps1   # 需管理员、Secure Boot 关闭
Restart-Computer

.\scripts\install-testcert.ps1     # 导入测试证书到 LocalMachine Root/TrustedPublisher
.\scripts\install-driver.ps1       # 校验签名后再安装并注册 UpperFilters
Restart-Computer

.\scripts\restore-driver.ps1 protect-on
Restart-Computer
.\scripts\restore-driver.ps1 status
```

判定：`sc query SysRestoreDriver` 为 RUNNING；保护开启后写入系统盘的文件在重启后回滚。

## 4. 蓝屏恢复（不能进系统时）

见 `deploy/client-package/scripts/recover-boot.txt`，核心步骤：

1. 进 WinRE → 命令提示符；
2. `reg load HKLM\IDV C:\Windows\System32\config\SYSTEM`（系统盘不一定是 C:）；
3. 从卷类 UpperFilters 中移除 `SysRestoreDriver`（保留其它过滤驱动）；
4. 删除 `Services\SysRestoreDriver`；
5. `reg unload HKLM\IDV`，重启。

**只删 `C:\Windows\System32\drivers\SysRestoreDriver.sys` 不能修复**：服务/过滤项仍引用它，仍会蓝屏。
