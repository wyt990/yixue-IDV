# 模块 07 — 有线与 WiFi 接入

> 问题：能否 PXE 加载初步系统后，在客户端配置网络、服务器 IP/端口，从而用 WiFi 做镜像传输？

---

## 1. 结论摘要

| 能力 | 结论 |
|------|------|
| **标准固件 PXE 直接走 WiFi** | **基本不可行**（PC 固件 PXE 几乎只认有线 NIC） |
| **有线 PXE/U 盘进入 PE 后，再连 WiFi 拉镜像** | **可行，建议作为二期能力** |
| **日常上课学生机用 WiFi 上网** | 与本系统装机链路独立；由系统镜像内网络配置负责 |
| **一期默认** | **机房有线 + Edge 同网段**；WiFi 为补充场景（临时教室、无法布线点） |

你的思路正确：**引导用有线（或 U 盘），大数据传输可切 WiFi**——前提是 PE 带好无线网卡驱动。

---

## 2. 推荐流程（WiFi 辅助部署）

```text
1. 有线插网线（或 U 盘 iPXE）→ 进入 idv-pe
2. PE 启动「网络向导」：
   - 选择网卡：有线 / WiFi
   - WiFi：SSID、加密、密码（可扫管理端下发的一次性配置码）
   - Center/Edge 地址：IP、端口、可选 TLS 指纹
3. 连通性检测（DNS 可选、HTTPS 心跳）
4. 领取任务 → 从 Edge（或经路由可达的 Edge）拉镜像
5. 写盘完成后，可提示拔网线；日常系统是否用 WiFi 由镜像内设置决定
```

### 配置下发方式

- PE 内手动填写（最少可用）。  
- 管理端生成 **短时配置票据**（二维码 / 6 位码），PE 输入后拉取 SSID 与 Edge 地址（密码不落长时间日志）。  
- Edge 对已登记 MAC 的有线会话自动给任务；WiFi 会话必须令牌，防蹭网刷写盘。

---

## 3. 限制与风险

| 风险 | 对策 |
|------|------|
| WiFi 驱动在 PE 中缺失 | 维护「PE 无线驱动包」；金样硬件分型号池 |
| 校园网认证（802.1X/门户） | 二期先支持 PSK；802.1X 单独立项 |
| 无线带宽与丢包 | 大镜像仍优先有线；WiFi 适合小批或增量 |
| 安全 | 写盘令牌 + Edge 白名单；禁止无令牌匿名拉全校镜像 |
| WOL 唤醒 | 多数无线网卡不支持，远程开机仍依赖有线 |

---

## 4. 与「纯无线教室」的关系

若教室 **完全无有线**：

- 不能依赖标准 PXE；改用 **U 盘 / 厂商引导 / 已安装 Agent 拉增量**。  
- 首装成本高，建议至少保留「首次有线装机或技术员 U 盘」。  

产品文案避免承诺「完全无线 PXE」。

---

## 5. PE 网络向导 UI（元素）

- 网卡列表（驱动是否加载成功）  
- WiFi 列表扫描、信号、锁图标  
- 服务器：`https://edge-host:port`  
- 测试按钮、失败原因（证书/超时/401）  
- 高级：静态 IP、代理（少见）  

---

## 6. 验收清单

- [x] 文档与销售话术不声称「固件级 WiFi PXE」  
- [ ] PE 可在有线引导后切换 WiFi 并完成至少一次完整部署（试点型号 / 真驱动）  
- [x] 可配置 Edge IP/端口并持久到本次任务会话（`network-wizard` → session JSON）  
- [x] 无令牌的 WiFi 客户端不能任意写盘（checkin 需 `X-Idv-Pe-Token`）  
- [x] 驱动不支持的网卡有明确报错（缺 SSID / 探测失败即报错；真驱动包滚动）  
- [x] PE WiFi 驱动包目录与 manifest 槽位（`pe/wifi-drivers/`；placeholder，生产需换签名 INF）  

---

## 7. 分期

| 内容 | 分期 |
|------|------|
| 有线 DHCP/PXE | 一期必做 |
| PE 手动填 Edge 地址（有线静态/跨网段） | 一期可做小增强 |
| WiFi 连接向导 + 驱动包 | 二期 |
| 配置二维码 / 802.1X | 三期或需求池 |
