# 模块 09 — 外部依赖与版本策略

> 诉求：项目用到的外部支持/组件保持**当前稳定最新**，避免「一做出来就过时」。  
> 基线核对日：2026-11-12（脚手架与每次大版本升级前须重新核对官网/crates.io/npm）

---

## 1. 结论摘要

- **原则**：默认采用各组件的 **最新 Stable / LTS**，不锁死多年前的大版本；用锁文件保证可复现，用自动化提醒升级。  
- **不做**：为「新」而用 nightly/alpha 作为生产默认；不把已停更的老栈写进基线（如 Rust Edition 2021 作为新建项目默认、axum 0.6、React 17、PostgreSQL 14 等）。  
- **总纲原「Edition 2021+」已过时**：新建工程默认 **Rust Edition 2024** + 当前 `stable` 工具链。  
- **允许的必要开源引导件**须跟上游大版本：当前 iPXE 已有 **2.x**，勿默认拷贝市面教程里的 1.x 老构建脚本当唯一方案。

---

## 2. 版本策略（开发约定）

| 规则 | 说明 |
|------|------|
| Stable 优先 | 语言、框架、数据库、Node 均选当前 Stable；Node 选 **Active LTS** |
| 锁文件入库 | 提交 `Cargo.lock`、前端 `pnpm-lock.yaml`/`package-lock.json` |
| 工具链钉住渠道 | 仓库根放 `rust-toolchain.toml`：`channel = "stable"`（或钉具体如 `1.99.1`，并定期 bump） |
| 依赖上界 | Cargo 用兼容上界（如 `axum = "0.8"`）+ lock；禁止无故抄写三年前的精确老版本当「推荐」 |
| 升级节奏 | 每月看安全公告；每季度主动升一轮小版本；主版本（axum 0.x→、PG 大版本）单独验收 |
| 自动化 | 启用 Renovate 或 GitHub Dependabot；CI 跑 `cargo audit` / `pnpm audit` |
| 许可证 | 新增依赖记入本模块「许可」栏；GPL 传染性组件进 PE/发行包前需评审 |
| 镜像源 | 国内可配 crates/npm/apk 镜像，但**版本号仍以官方 Stable 为准**，不用镜像里的过期缓存当真理 |

### 「最新」的边界

| 采用 | 暂缓 |
|------|------|
| crates.io / npm 上该包最新正式版 | `-alpha` / `-rc` 除非专项验证 |
| PostgreSQL 当前大版本的最新小版本 | 学校若统一只给 PG 16，可降，但文档注明「环境约束」而非「项目选型过时」 |
| iPXE 官方发布线最新 major | 随意第三方魔改 PXE 包且无人维护 |
| Alpine 当前 stable 分支构建 PE | 随意用 CentOS 7 类已 EOL 根文件系统做 PE |

## 4. 总纲里原先缺少、现予补充的点

1. **Edition / 工具链写死过旧**：已改为 2024 + stable 跟踪。  
2. **无「依赖保鲜」机制**：现规定 lock + audit + 季度升级。  
3. **未钉前端世代**：明确 React 19 / Vue 3.5 + Vite 8，避免脚手架生成旧模板。  
4. **未钉 iPXE 大版本**：明确跟 2.x。  
5. **未钉 PE 发行版**：明确 Alpine 当前 stable，避免教程拷贝 EOL 系统。  
6. **未钉 PostgreSQL 大版本**：明确 18.x 为默认目标（环境不够可降但记约束）。  
7. **TLS/密码学默认**：rustls 优先。  
8. **OpenAPI / 审计工具**：列为推荐，利于长期不腐化。  
9. **compose 镜像标签**：钉版本并在本表登记，避免静默漂到未知版本或反之永不过期。
