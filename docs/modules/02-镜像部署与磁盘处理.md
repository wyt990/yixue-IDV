# 模块 02 — 镜像部署与磁盘处理

> 问题：同步镜像前，客户端原有系统是否需要格式化硬盘？

---

## 1. 结论摘要

| 动作 | 是否要先「格式化」 | 说明 |
|------|-------------------|------|
| **Edge 同步镜像**（中心 → 边缘缓存） | **否** | 只读写服务器磁盘上的镜像文件，不动学生机 |
| **对学生机部署（deploy）** | **通常不必单独格式化** | 写入镜像本身会覆盖目标分区/磁盘内容，等价于重建系统区 |
| **采集（capture）** | **否** | 只读金样机磁盘（或快照读），不格式化 |
| **保留数据分区的部署** | **按策略** | 只覆盖系统分区，数据分区可保留不格式化 |
| **整盘换系统 / 分区表变更** | **先清分区表再按镜像布局重建** | 仍由部署流程完成，不必管理员手工先格式化一遍 |

**给网管的一句话**：部署不是「先格式化再拷文件」的两步人工活；选好磁盘策略后，任务会覆盖该覆盖的区域。原系统数据若在被覆盖分区内，**会丢失**，需在任务确认框写清楚。

---

## 2. 三个易混概念

```text
① 镜像同步 sync_image     ：Center/Edge 存储之间复制镜像包
② 客户端部署 deploy       ：PE 把镜像写入学生机硬盘
③ 文件系统格式化 format   ：创建空文件系统（部署里往往被「写镜像」取代）
```

用户说的「同步镜像」在口语里有时指 ①，有时指 ②。本产品在界面文案中强制区分：

- **同步到边缘**：①  
- **部署到终端**：②  

---

## 3. 部署磁盘策略（一期就要可配）

任务创建时选择 **DiskPlan**：

| 策略 ID | 行为 | 适用 |
|---------|------|------|
| `wipe_target_partitions` | 按镜像 meta 重建并写入列出的分区；未列出的分区可保留 | 常见：系统盘重装，D 盘课堂数据保留 |
| `wipe_whole_disk` | 重建整盘分区表并写入镜像中所有分区 | 新机、分区表与金样不一致、换系统类型 |
| `write_system_only` | 仅写入标记为 `role=system` 的分区 | 镜像与现网分区布局兼容时 |

### 安全确认（UI 必做）

二次确认展示：

- 目标磁盘序列号 / 容量  
- 将覆盖的分区列表  
- 「以下分区将保留」列表  
- 明确句：**被覆盖分区上的原系统与数据不可恢复**

### 是否「先格式化」

- 块级镜像写入：直接按块书写，**不需要**先 `mkfs`。  
- 若未来支持文件级（WIM 等）：可能先建分区 + 格式化再展开文件；那是写盘插件内部步骤，仍不是管理员手工预格式化。

---

## 4. 原系统还在时的推荐流程

1. 确认机房已备份需保留数据（或确认使用「保留数据分区」策略）。  
2. Edge 已有镜像副本 `ready`。  
3. 创建部署任务 → 学生机 PXE 进 PE（原系统离线，由 PE 占盘）。  
4. PE 校验磁盘与策略 → 写入 → 校验 → 报告成功。  
5. 重启进新系统。

原 Windows/Linux 不必先进入系统里点格式化；**PXE 维护环境离线写盘**即可。

---

## 5. 失败与半写入

- 写入中失败：任务标记 `failed`，磁盘可能处于不可启动状态（预期风险）。  
- 支持「同一任务重试 / 重新部署」；不提供「自动神奇修复原系统」。  
- 校验失败不得报成功。

## 7. 分期

- 一期阶段 4：`wipe_whole_disk` + `wipe_target_partitions` 至少一种保留数据策略。  
- 更复杂的多盘服务器级策略：需求池。
