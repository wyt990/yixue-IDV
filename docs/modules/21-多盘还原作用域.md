# 模块 21 — 多盘还原与模式保护范围

> 需求：机器有多个固定盘（C/D/E/F/G…）时：
> - **教学/开机还原模式**：所有非移动盘都还原（系统盘 + 数据盘）；
> - **考试模式**：只还原系统盘，D/E/F/G 等数据盘保留；
> - U 盘/移动硬盘/网络盘始终不保护。
>
> 旧实现只把 `system`（系统盘）列进 `protect_volumes`，所以只有 C 盘冻结；
> 本模块新增“模式保护范围”，由 Center 下发，Agent 按固定盘枚举后逐卷 arm。

---

## 1. 数据模型

`mode_policies` 新增列（迁移 `020_mode_protect_scope.sql`）：

```text
protect_scope TEXT NOT NULL DEFAULT 'system'
  system    = 仅系统盘（C:）
  all_fixed = 所有固定 NTFS 盘（C: D: E: …）
```

默认种子：

| 模式 | restore | protect_scope | 效果 |
|------|---------|---------------|------|
| teaching（教学/开机还原） | reboot | **all_fixed** | 所有固定盘冻结，重启还原 |
| exam（考试） | reboot | system | 仅 C 盘还原，数据盘保留 |
| office（办公） | off | system | 不自动还原 |
| manual（手动） | manual | system | 手动触发，仅系统盘 |

已有数据库升级时，迁移会把 `teaching` 设为 `all_fixed`；自定义模式保持 `system`。

---

## 2. 修改保护范围

API（管理端暂未做表单，可直接调用）：

```powershell
# 1) 登录拿 token
$t = (Invoke-RestMethod -Method Post -Uri http://10.110.0.1:8080/api/v1/auth/login `
  -ContentType application/json -Body '{"username":"admin","password":"admin123"}').token

# 2) 查模式 id
Invoke-RestMethod http://10.110.0.1:8080/api/v1/modes -Headers @{Authorization="Bearer $t"} |
  Select-Object id,name,restore,protect_scope

# 3) 改成所有固定盘（teaching）或仅系统盘（exam）
Invoke-RestMethod -Method Post -Uri http://10.110.0.1:8080/api/v1/modes/<模式id>/schedule `
  -Headers @{Authorization="Bearer $t"} -ContentType application/json `
  -Body '{"protect_scope":"all_fixed"}'
```

新建模式时 `POST /api/v1/modes` 也可带 `"protect_scope":"all_fixed"`。

---

## 3. Agent 执行逻辑

- Center 心跳下发 `desired_state.restore.protect_volumes = ["all_fixed"]` 或 `["system"]`；
- Agent `StateFileDriver::volume_roots` 解析 `all_fixed`：
  - 枚举 C:–Z:，仅保留 `DRIVE_FIXED` 且文件系统为 **NTFS** 的卷；
  - 跳过 U 盘、移动硬盘、网络盘、无盘符分区；
- 对每个卷根写 `_qh_protect_state.data=1`（驱动直通文件），重启后该卷进入冻结/还原；
- 改为 `system` 或关闭模式时写 0 / 只影响系统卷；
- **范围变更需要重启生效**：Agent 应用 pending 状态后会自动重启一次（`apply_pending_store` 返回需要重启时）。

> 注意：只有 **NTFS + 有盘符 + 固定盘** 会被 arm；exFAT/ReFS、动态卷、BitLocker 卷需单独验证。
> 驱动为卷过滤驱动，D/E 等卷会在重启后生效。

---

## 4. 验收

1. 机器有 C + D（均 NTFS）；
2. 机房切到 teaching 模式 → 客户端自动重启；
3. 重启后确认各盘根目录存在隐藏系统文件 `_qh_protect_state.data`（首字节 1）：
   ```powershell
   foreach ($d in 'C','D','E') {
     $f = "${d}:\_qh_protect_state.data"
     if (Test-Path $f) { "{0}: {1}" -f $d, ([System.IO.File]::ReadAllBytes($f)[0]) }
   }
   ```
4. 在 D 盘写一个测试文件 → 重启 → 文件应消失（还原）；
5. 切到 exam 模式并重启 → C 盘还原、D 盘测试文件保留；
6. 切回 office/关闭还原 → 重启后所有盘不再冻结。

---

## 5. 排障

| 现象 | 检查 |
|---|---|
| D 盘仍不还原 | D 是否 NTFS/固定盘/有盘符；`_qh_protect_state.data` 首字节是否为 1；驱动是否加载 |
| 只有 C 被保护 | 模式 `protect_scope` 是否 `all_fixed`；Center 是否已重启应用迁移 020；客户端是否重启过 |
| 切模式后没重启 | 确认 Agent 常驻服务在跑；看 `agent_sessions.detail` 的 identity/apply 状态 |
| 想保护无盘符分区 | 当前仅支持有盘符的固定 NTFS 卷；系统保留/恢复分区默认不 arm |
