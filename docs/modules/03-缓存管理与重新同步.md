# 模块 03 — 缓存管理与重新同步

> 问题：重新同步时，是否要有清空缓存功能？

---

## 1. 结论摘要

**要有。** 缓存管理是 500+ / 多 Edge 场景的运维标配。

| 能力 | 是否需要 | 说明 |
|------|----------|------|
| 查看各 Edge 镜像副本与占用 | 是 | 副本状态 `syncing/ready/stale/error` |
| 重新同步（增量拉取缺失块/整包校验修复） | 是 | 不必每次先删 |
| **清空指定镜像在某 Edge 的缓存** | 是 | 版本作废、磁盘满、校验长期失败 |
| **清空某 Edge 全部镜像缓存** | 是 | 危险操作，强确认 |
| 同步前强制「先清空再拉」 | 可选开关 | 默认关闭；怀疑缓存污染时开启 |

---

## 2. 缓存层级

```text
Center 权威库          ─ 不轻易删；删镜像要检查是否仍有 Edge 引用
Edge 镜像缓存          ─ 本模块重点
学生机本地（P2P 已收块）─ 见模块 05；可单独「清理客户端临时块」
PE 下载临时目录        ─ 任务结束清理；失败可保留便于排障（可配）
```

---

## 3. 操作定义

### 3.1 重新同步 `resync`

1. 对比 Center 与 Edge 的 checksum / 分片清单。  
2. 缺啥补啥；可选「全量重下」。  
3. 成功后副本 → `ready`，失败 → `error` 并保留旧文件或标记不可用（策略可配）。

**默认**：不先清空，断点续传 / 校验修复。

### 3.2 清空缓存 `purge`

| API/动作 | 范围 | 前置 |
|----------|------|------|
| `purge_replica(edge, image)` | 单个镜像副本 | 无进行中的该镜像部署任务 |
| `purge_edge_all(edge)` | 该 Edge 全部镜像 | 二次确认 + 输入节点名 |
| `purge_center_image` | 中心镜像 | 更高权限；需无依赖或强制级联策略 |

清空后副本状态 → `absent`，需重新 `sync` 才能部署。

### 3.3 「先清空再同步」`purge_and_sync`

用于：checksum 对不上、人工怀疑文件损坏、更换压缩算法/格式版本。

---

## 4. 磁盘与水位

- Edge 配置 `cache_path`、`cache_quota`、水位告警（如 85%/95%）。  
- 配额不足时：拒绝新同步并告警；可提供「按最近使用 LRU 建议清理列表」（二期可自动，一期先手动）。  

---

## 5. 界面要点

- 镜像详情页：各 Edge 副本表 + 按钮「同步」「重新校验」「清空缓存」。  
- Edge 详情页：缓存占用条 + 「清理…」向导。  
- 所有清空操作进审计日志。

---

## 6. 验收清单

- [x] 可查看 Edge 上镜像副本列表与状态/进度（阶段 2；占用字节可后续增强）  
- [x] 可不清空而重新同步/校验修复  
- [x] 可清空单镜像缓存后再次同步  
- [x] 可清空 Edge 全部缓存（API：`POST /api/v1/edges/{id}/purge_all`；UI 强确认可后续补）  
- [x] 提供「清空并同步」组合动作（`purge_first` / `purge_and_sync`）  
- [ ] 危险操作有审计记录（阶段后续补审计表）  
- [x] 整 Edge 清空（API + 管理端输入节点名确认）  
- [x] 缓存水位告警（`cache_quota_bytes` / `cache_level` 心跳上报）  

---

## 7. 分期

- 阶段 2：同步进度 + 基础重新同步。  
- 阶段 2～4：单镜像清空、配额展示。  
- 阶段 5：整 Edge 清空、水位告警；LRU 自动清理仍属后续增强。
