# 模块 06 — 还原策略与多模式（办公 / 考试等）

> 问题：不还原时（办公模式、考试模式等），怎样让部分数据不受还原影响？

---

## 1. 结论摘要

**要支持「分区/卷角色 + 工作模式」**，不能只有「整机一键还原」。

| 模式示例 | 系统区 | 用户数据区 | 典型用途 |
|----------|--------|------------|----------|
| 教学还原 | 每次开机还原 | 可选还原或清空 | 普通机房课 |
| 考试模式 | 还原到标准卷 | 考试卷可写但交卷后清理；禁 U 盘等策略 | 期末考 |
| 办公模式 | **不还原** 或仅手动还原 | **持久保留** | 教师机、教研室 |
| 维护模式 | 不还原 | — | 打补丁、装软件后重新封板 |

「不受还原影响」的数据必须落在 **标记为持久的分区/目录/虚拟盘** 上，而不是指望还原引擎「智能识别文档」。

---

## 2. 磁盘角色模型

镜像与本地布局统一使用角色标签（写入 `image.meta` / 本地策略）：

| 角色 | 含义 | 开机还原时 |
|------|------|------------|
| `system` | 操作系统与标准软件 | **恢复到基线** |
| `persistent` | 持久数据（文档、教学提交、用户配置） | **保留** |
| `volatile` | 临时（下载、试卷草稿区） | 可清空或还原到空 |
| `shared` | 只读教材库（可选） | 保留；权限只读 |

### 实现路径（二期选型，可并行预研）

1. **分区级保护（优先推荐机房）**：系统分区做还原，数据分区不纳入还原范围。简单、好讲清楚。  
2. **文件驱动/过滤驱动（Windows）**：更细，但驱动签名与信创差异成本高。  
3. **本地虚拟盘差分（更接近狭义 IDV）**：系统盘为差分，提交/丢弃；实现重，可作三期。

**一期不做还原**；采集镜像时建议金样机已按「系统盘 + 数据盘」分区，避免二期重采。

## 3. 工作模式（策略对象）

```text
ModePolicy {
  name: 教学还原 | 考试 | 办公 | 自定义
  restore: reboot | manual | off
  volumes: { system: restore, persistent: keep, volatile: wipe_on_boot? }
  restrictions: { usb, network_filter, app_whitelist }  // 考试可增强
  apply_to: lab_ids[] | client_ids[]
  schedule: 永久 | 时间窗（如考试当天）
}
```

- **办公模式**：`restore=off`，`persistent=keep`；教师可长期装软件（风险：环境漂移，需定期「重新封板」采集）。  
- **考试模式**：`restore=reboot` 或开考前强制还原；`persistent` 指向交卷目录；可选禁用外设。  
- **不还原 ≠ 没有管理**：仍可心跳、远程关机、下一时段切回教学还原。

---

## 4. 用户可见行为

- 学生机托盘/登录前水印可显示当前模式（考试/还原中等）。  
- 管理端可按机房一键切换模式，并显示「下一开机生效」或「立即重启生效」。  
- 切换到办公模式需权限（避免学生自己关还原）。

## 7. 卷过滤驱动还原（2026-11-13 本刀）

**产品选择**：日常开机还原走 **卷过滤写时重定向**（参考 `drivers/sys-restore`，Apache-2.0），**不做**开机镜像写回；全量 PXE 仅用于封板/换金样。

| 项 | 说明 |
|----|------|
| 策略 | Center ModePolicy → Agent 心跳 `desired_state`（`frozen` / `revision`） |
| 生效 | 默认 `next_reboot`：写入 pending，开机 `idv-agent sync-policy --apply` |
| 无驱动 | Agent MockFile 仅联调策略，不提供真还原 |
| 管控规划 | 协助/硬件/网址/分发收集等见 [endpoint-restore-control-design](../plans/2026-11-13-endpoint-restore-control-design.md) |

验收脚本：`deploy/scripts/stage-restore-driver-accept.ps1`。
